Lesson 47: Containers and Docker for Spring Boot Applications

Welcome to a major transition point.

So far we learned how to build backend systems:

  • Spring Boot APIs
  • Security
  • Databases
  • Redis
  • Messaging
  • Observability

But a real question appears:

How do we take our application and run it reliably on another machine?

Example:

You develop on your laptop:

Windows/Mac

Java 21

PostgreSQL 16

Redis

RabbitMQ

Production server:

Linux

Different Java version

Different configuration

Different installed software

Problems happen.

Docker solves this.

1. What is Docker?

Docker packages your application with everything it needs.

Instead of:

 id="oldway"

Server

Install Java

Install PostgreSQL

Install Redis

Copy application

Configure everything

We create:

 id="dockerway"

Docker Image

+
Application

+
Java Runtime

+
Dependencies

Then run it anywhere.

2. Virtual machines vs containers

Before Docker:

Companies used virtual machines.

Example:

 id="vm"

Physical Server

        |

        v

Virtual Machine

        |

        v

Operating System

        |

        v

Application

Problem:

A full operating system for every application.

Heavy.

Docker:

 id="container"

Physical Server

        |

        v

Docker Engine

   |       |       |

   v       v       v

 App1    App2    App3

Containers share the host OS.

Much lighter.

3. Important Docker concepts

Docker has four main concepts:

1. Image

2. Container

3. Dockerfile

4. Registry

4. Docker Image

An image is a blueprint.

Like a class in Java.

Example:

 id="image"

Spring Boot Application Image

Contains:

- Java
- application.jar
- configuration

You create an image once.

5. Docker Container

A container is a running instance of an image.

Like an object in Java.

Example:

Image:

 id="java"

ProjectHub Image

Run:

docker run projecthub

Creates:

 id="container"

ProjectHub Container

6. Docker Registry

A place to store images.

Example:

Docker Hub

You can:

push:

Your laptop

   |
   v

Docker Hub

pull:

Server

   |
   v

Docker Hub

7. The Docker workflow

Typical workflow:

 id="workflow"

Write code

    |

Build Spring Boot jar

    |

Create Docker image

    |

Push image

    |

Deploy container

8. Spring Boot application without Docker

Normally:

Build:

mvn clean package

Creates:

 id="jar"

projecthub.jar

Run:

java -jar projecthub.jar

Works on your machine.

9. Dockerfile

A Dockerfile tells Docker how to build the image.

Example:

FROM eclipse-temurin:21-jdk

WORKDIR /app

COPY target/projecthub.jar app.jar

EXPOSE 8080

ENTRYPOINT [
"java",
"-jar",
"app.jar"
]

Let’s understand it.

FROM​

FROM eclipse-temurin:21-jdk

Means:

Start with Java 21.

Base image:

Java runtime

WORKDIR​

WORKDIR /app

Inside container:

/app

becomes the working folder.

COPY​

COPY target/projecthub.jar app.jar

Copy your application.

Before:

Laptop:

target/projecthub.jar

After:

Container:

app.jar

EXPOSE​

EXPOSE 8080

Documents that the application uses:

port 8080

ENTRYPOINT​

ENTRYPOINT [
"java",
"-jar",
"app.jar"
]

Command executed when container starts.

10. Build Docker image

Inside project:

docker build -t projecthub .

Meaning:

Create image:

projecthub

Check images:

docker images

Example:

REPOSITORY

projecthub

TAG

latest

11. Run container

docker run -p 8080:8080 projecthub

Meaning:

Host:

8080

maps to:

Container:

8080

Now:

Browser

localhost:8080

        |

        v

Spring Boot Container

12. Container lifecycle

Create:

docker create

Start:

docker start

Stop:

docker stop

Remove:

docker rm

13. Viewing containers

Running:

docker ps

All:

docker ps -a

Example:

CONTAINER ID

abc123

IMAGE

projecthub

STATUS

Up 5 minutes

14. Logs

Very important.

Application logs:

docker logs projecthub

Example:

Started ProjectApplication

Tomcat running on port 8080

15. Environment variables

Never hardcode production values.

Bad:

spring.datasource.password=password123

Better:

spring.datasource.password=${DB_PASSWORD}

Docker:

docker run \
-e DB_PASSWORD=mysecret \
projecthub

16. Spring Boot configuration

Example:

application.yml:

spring:
 datasource:
   url: ${DATABASE_URL}
   username: ${DATABASE_USER}
   password: ${DATABASE_PASSWORD}

Container receives:

DATABASE_URL

DATABASE_USER

DATABASE_PASSWORD

17. Docker Compose

A real application has multiple services.

ProjectHub:

 id="services"

Spring Boot

+

PostgreSQL

+

Redis

+

RabbitMQ

Running manually:

docker run postgres

docker run redis

docker run rabbitmq

docker run projecthub

Painful.

Docker Compose:

One file:

docker-compose.yml

defines everything.

18. Example Docker Compose

services:

  app:
    image: projecthub
    ports:
      - "8080:8080"

  postgres:
    image: postgres
    environment:
      POSTGRES_PASSWORD: password

  redis:
    image: redis

  rabbitmq:
    image: rabbitmq

Start:

docker compose up

Now:

 id="compose"

ProjectHub

     |

     +---- PostgreSQL

     +---- Redis

     +---- RabbitMQ

19. Docker networking

Containers can talk using service names.

Example:

services:

 postgres:
   image: postgres

 app:
   image: projecthub

Inside Spring:

Instead of:

localhost

Use:

postgres

Because Docker creates a network.

20. Database persistence problem

Containers are temporary.

Example:

docker rm postgres

Database disappears.

Problem.

Solution:

Volumes.

21. Docker volumes

A volume stores data outside the container.

Example:

postgres:

 volumes:

 - postgres-data:/var/lib/postgresql/data

Now:

Container deleted:

Database data remains

22. Multi-stage Docker builds

A production improvement.

Bad:

FROM jdk

copy source

build

run

Image contains:

  • source code
  • Maven
  • build tools

Large.

Better:

Stage 1:

Build:

FROM maven

compile application

Stage 2:

Run:

FROM java-runtime

copy jar

Result:

Small image.

Example:

FROM maven:3.9 AS build

WORKDIR /app

COPY . .

RUN mvn package


FROM eclipse-temurin:21

COPY --from=build \
target/*.jar app.jar

ENTRYPOINT [
"java",
"-jar",
"app.jar"
]

23. Docker security basics

Do not run as root.

Bad:

Container

root user

Better:

USER appuser

Do not store secrets:

Bad:

ENV PASSWORD=12345

Use:

  • environment variables
  • secret managers

24. Health checks

Docker can check your application.

Example:

HEALTHCHECK CMD curl localhost:8080/actuator/health

Application:

UP

Container:

healthy

Code

27. Docker vs Kubernetes

Docker:

Creates and runs containers.

Kubernetes:

Manages many containers.

Example:

Docker:

Run one ProjectHub container

Kubernetes:

Run 100 ProjectHub containers

Replace failed containers

Scale automatically

Load balance
